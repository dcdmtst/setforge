# Исполнитель: запрос и ответ

У каждого задания есть `jobs/JOB/request.json` и `schema.json`. Они определяют
точный контракт; не собирайте свой сокращённый запрос из брифа. Входы включают
роль, инструкции, контекст, изображения с ролями и схему ответа. Порядок и роли
изображений важны: эталон стиля, канон и цель редактирования не взаимозаменяемы.

## Файловый worker

`claim` возвращает ID задания, токен и владельца. Прочитайте запрос, выполните
одну попытку и сохраните JSON по схеме. Для изображения: `image_path` к настоящему
PNG и строка `note`. Для приёмки: точные критерии, наблюдения и art_review, если
он предусмотрен заданием. Относительные пути изображения считаются от корня
заказа; абсолютный локальный путь допустим и будет импортирован в историю.

`prepare-job` проверяет входы и возвращает список ещё не просмотренных эталонов.
`validate-response` проверяет форму ответа, но не принимает содержимое. Затем
`deliver` с точными ID/worker/token. Только координатор применяет ответ.

Для встроенного imagegen обязательна подготовка ограниченного набора через
`prepare-job.image_call`, затем `image-start` → один вызов → `image-finish`.
Последняя команда пишет ответ и метаданные сама. Не передавайте все images
инструменту с лимитом5 и не пишите таймеры/хеши вручную.
Подробности и ошибки: [image-execution.md](image-execution.md).

Для долгой работы продлевайте аренду через `heartbeat`. По таймауту картинки
не делайте новый вызов автоматически: исходный результат мог уже создаться.
Повторный вызов — отдельная учтённая попытка, не внутренний retry адаптера.

## Command-адаптер

Локальная конфигурация, пример структуры:

```json
{
  "type": "command",
  "argv": ["{python}", "/PATH/TO/YOUR/worker.py", "--request", "{request}", "--response", "{response}"],
  "estimated_cost": 0,
  "zero_cost": true,
  "supports_images": true
}
```

`{python}` — текущий интерпретатор; остальные подстановки — абсолютные пути.
Вызов идёт списком аргументов без shell, cwd — каталог заказа. Запрос также
передаётся JSON через stdin. Верните JSON в файл response (предпочтительно)
или stdout; служебные сообщения — в stderr. Worker должен проверять собственную
бесплатность, права доступа и поддерживаемые изображения. Не устанавливайте
`zero_cost:true` для тарифицируемого API ради обхода бюджета.

Запуск настроенного исполнителя: `setforge worker --run RUN --worker NAME
--role image` (или planner/reviewer/flex). Worker выполняет работу вне общей
блокировки. Координатор запускается отдельно. Произвольные shell-строки, ключи
в argv и неподтверждённые фоновые retries не нужны.

Для CI или GPU-фермы можно реализовать собственный внешний диспетчер с теми же
JSON-контрактами. Встроенная SQLite-очередь предполагает общую локальную папку;
она не является распределённым облачным брокером.

# Вызов генератора без ручных служебных записей

Для встроенного imagegen используйте `image-start` → один вызов инструмента →
`image-finish`. Это часть работы исполнителя, без вопросов продюсеру и ручного
редактирования JSON. Команды не вызывают модель и не принимают арт.

## Подготовка референсов

`prepare-job` для задания image возвращает `image_call`: готовый промпт,
абсолютные `referenced_image_paths`, хеши, полный список входов и причины пропусков.
Не передавайте генератору весь `request.images` напрямую. Он остаётся полным
списком для визуального просмотра и независимой приёмки.

У builtin imagegen максимум **5 входных изображений суммарно**: эталоны, канон
и цель редактирования занимают одни и те же слоты. Выбор выполняется кодом:

1. Цель редактирования и все источники обязательного канона.
2. Оригинальные эталоны, указанные для конкретной карточки.
3. Общие оригинальные эталоны, пока есть место.

Одинаковые байты занимают один слот; дополнительные роли записываются как
aliases. Если обязательные входы и хотя бы один доступный оригинальный эталон
не помещаются, модель не вызывается. Исполнитель должен уменьшить число
избыточных ракурсов источника на этапе планирования либо использовать другой
подходящий генератор. Нельзя молча выбросить персонажа или заменить эталон
сгенерированным артом. Непопавшие в вызов оригиналы остаются доступны ревьюеру.

`providers.image.max_images` задаёт лимит среды; у нового проекта он равен 5.
Для другого инструмента задайте его реальный лимит в проекте до нового заказа
и передайте `image-start --tool ACTUAL_TOOL --max-images N`. Для imagegen
потолок 5 действует даже при завышенной настройке. Больший лимит не означает
разрешения на платный сервис. К приёмке лимит генератора не применяется.

## Один вызов — одна запись

После claim и просмотра входов выполните команды тем же `.venv` Python.
Здесь RUN — **абсолютный** корень заказа, JOB/WORKER/TOKEN — точная аренда.

```text
setforge prepare-job --run RUN --job JOB --worker WORKER
setforge image-start --run RUN --job JOB --worker WORKER --token TOKEN
```

Из JSON `image-start` передайте инструменту без изменений `prompt`,
`referenced_image_paths`, `transparent_background`. Если промпт нужно дополнить,
сначала сохраните его и задайте `--prompt-file FILE` при image-start; после старта
промпт уже не меняйте. Используйте подготовленные пути, а не недокументированный
набор последних картинок чата. Один вызов, без внутренних повторов.

Сразу после получения пути к настоящему PNG:

```text
setforge image-finish --run RUN --job JOB --worker WORKER --token TOKEN --image ABSOLUTE_TOOL_PNG
```

CLI сам сохраняет исходный PNG без изменений, вычисляет SHA256, записывает
`started_at`, `ended_at`, `received`, `seconds`, инструмент, модель и исполнителя.
Имена полей фиксированы. Известную модель передавайте через `--model`; если она
не раскрыта инструментом, оставьте `unspecified`, не угадывайте её версию.

Файлы в jobs/JOB:

- `generation-inputs.json` — фактический выбор, полные входы, хеши и пропуски;
- `generation-prompt.txt` — точный промпт;
- `generation-record.json` — результат, путь источника, хеш и время;
- `generation-tool-timing.json` — те же границы в формате отчёта;
- `image-response.json` — готовый ответ для validate-response/deliver.

Относительные пути считаются от RUN, а не от текущей папки shell. Время пишется
в UTC автоматически: от image-start непосредственно перед вызовом до
image-finish сразу после возврата. Это **интервал вызова исполнителя с накладными
расходами отправки/возврата**, не чистое вычислительное время модели. Подготовку,
просмотр и чтение документации завершайте до старта; не вставляйте их между
этими командами. Полная работа claim→deliver измеряется отдельно.

При ошибке инструмента закройте тот же таймер:

```text
setforge image-finish --run RUN --job JOB --worker WORKER --token TOKEN --error "Tool error without a usable PNG"
setforge abandon --run RUN --job JOB --worker WORKER --token TOKEN --reason "Recorded tool failure"
```

Для успеха используйте путь `response` из image-finish в validate-response и
deliver. Запись метаданных не заменяет технические и художественные гейты.
Закрытая попытка не перезаписывается; новый вызов требует нового задания.
Если связь потеряна, сначала найдите существующий PNG и закройте открытую
запись. Наличие открытого таймера не даёт разрешения на повторную генерацию.
Если момент завершения утрачен, не выдавайте позднее закрытие за время модели:
сохраните ограничение в note и истории, не реконструируйте его по датам файлов.

Командный исполнитель может использовать тот же CLI вокруг своего инструмента
внешней очереди. Если он запускается через `setforge worker`, адаптеру нужно
самому записывать эквивалентную телеметрию вокруг настоящего вызова модели;
не оборачивайте весь процесс адаптера и не называйте это временем модели.

# Загрузить подготовленный исходный репозиторий

Эта папка — отдельная публикационная копия. Рабочее окружение и эксперименты
за её пределами не нужны. Загружайте **только содержимое этой папки** либо
подготовленный source ZIP, не родительский каталог.

1. На отдельном аккаунте создайте пустой публичный репозиторий без автоматически
   созданных README/лицензии. В этой поставке уже подготовлена MIT для кода;
   перед публикацией проверьте, что эта лицензия вам подходит.
2. Откройте эту папку в GitHub Desktop или другом Git-клиенте и войдите именно
   в нужный аккаунт. Сначала просмотрите список файлов, затем создайте первый
   коммит и опубликуйте в пустой репозиторий. История наших экспериментов не включена.
3. Перед коммитом:

```text
python scripts/publication_check.py --tracked
git diff --cached --stat
```

Если вы распаковали source ZIP, сначала `git init -b main`, затем `git add .`,
проверка выше и первый коммит. Не меняйте глобальные имя/почту Git ради проекта:
задайте их локально в репозитории, используя профиль и приватный noreply-адрес
**нового** аккаунта. Готовая папка не содержит коммита с личностью прежнего аккаунта.

4. Подключите адрес вашего репозитория и отправьте main. Для CLI:

```text
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

Имена/URL аккаунтов и ключи намеренно не предзаполнены. Сам файл LICENSE не
содержит личных данных. Не сохраняйте токены в remote URL.

## Что должно отсутствовать

Реальные референсы и арты, промежуточные/финальные результаты, брифы заказов,
задания, отчёты и замеры экспериментов, `.setforge/`, `.venv/`, ключи, логи,
локальные настройки и весовые файлы моделей. Исходный пример JSON-брифа и
синтетические тестовые процедуры допустимы; реальные изображения не нужны.

Узкое исключение по запросу владельца — пять PNG-групп звёзд интерфейса
`src/setforge/defaults/ui/rating-stars-[1-5].png` и их происхождение в JSON.
Они сохраняют исходное оформление, включая дугу из пяти звёзд; MIT на них
не распространяется (NOTICE.md). Проверка сверяет формат, размеры и хеши.
Это исключение не разрешает публикацию других референсов или результатов.

`.gitignore` защищает типичные runtime-пути. `publication_check.py --tracked`
дополнительно проверяет точный список отслеживаемых файлов, бинарные материалы,
типовые личные пути/токены и неизменность ядра. Это дополнительная проверка,
а не доказательство отсутствия любого возможного секрета: просмотрите первый diff.

Сборка source ZIP из явного allowlist:

```text
python scripts/publication_check.py --tracked --archive ../setforge-source.zip
```

Команда не включает `.git`, окружение, runtime или файлы вне списка исходников.
Автоматический workflow проверяет код на Windows/Linux; модельные вызовы и
загрузка результатов в публичный репозиторий в нём отсутствуют.
